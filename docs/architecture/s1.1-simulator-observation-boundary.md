# S1.1 Panthera Simulator Observation Boundary

## Purpose

The first native-host round trip proved Ubuntu, NVIDIA and Vulkan enumeration, but it did not prove the Panthera simulator observation contract.

A direct source audit of the pinned Panthera/RoboTwin tree found an important distinction that the project must preserve:

- RoboTwin Base_Task.get_obs() writes single-arm joint_action from Robot.get_left_arm_jointState().
- Robot.get_left_arm_jointState() reads each joint drive target, not the articulation qpos.
- Robot.get_left_arm_real_jointState() reads the articulation qpos and is the correct available source for simulated measured joint position.

Therefore joint_action is a commanded/target signal. It must never be silently relabeled as measured proprioception.


## Project-owned contract

The stable boundary is implemented in:

- src/vla_robot_sorting/contracts/simulation.py
- src/vla_robot_sorting/simulation/panthera_observation.py

SimulatorObservation contains:

- one JointState with Panthera joint order joint1 through joint6;
- one normalized gripper state;
- typed camera frames;
- scene/transform revision identifiers;
- explicit backend metadata.

The approved S1.1 RGB configuration requires both:

- head_camera;
- wrist_camera.

The mapper accepts the vendor observation and the real joint state as separate inputs. The vendor drive-target vector may be retained as diagnostic metadata, but it is never used to populate JointState.positions.


## Linux proof gate

scripts/linux/probe_panthera_observation.py initializes the approved single-arm Panthera task without executing the task trajectory, then captures:

1. Base_Task.get_obs() for head/wrist RGB;
2. Robot.get_left_arm_real_jointState() for actual articulation qpos;
3. Robot.get_left_arm_jointState() separately as the drive-target diagnostic;
4. Base_Task.single_arm_setup invariants.

The probe emits machine-readable JSON into the S1.1 evidence directory.

The canonical vendor episode remains a separate gate. Passing this observation probe proves the project-owned observation mapping only; it does not prove pick/place task success, collision behavior or controller quality.

## Required evidence before S1.1 can be complete

- both RGB cameras map successfully and have positive dimensions;
- actual qpos has exactly six Panthera arm joints plus one normalized gripper value;
- observation metadata identifies get_left_arm_real_jointState as the proprioception source;
- single-arm setup reports one articulation and one wrist camera;
- canonical safe-motion smoke subsequently succeeds;
- episode HDF5/video/resource evidence passes its existing checks.
