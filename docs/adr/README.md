# Architecture Decision Records

Use ADRs for decisions that affect subsystem interfaces, reproducibility, simulator/control architecture, dependency selection, safety, experiment interpretation, or future Sprint 2 portability.

Naming: `NNNN-short-title.md`.

Each ADR should contain:
- Status: Proposed / Accepted / Superseded
- Context
- Decision
- Alternatives considered
- Consequences
- Evidence / references
- Date

PO approval is required only when the decision changes locked project scope. Routine engineering ADRs may be accepted by the technical execution team and summarized in `docs/DECISIONS.md`.
